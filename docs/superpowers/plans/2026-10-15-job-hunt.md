# Job Hunt Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (chosen: Native — user said "get building"). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Daily CV-matched LinkedIn job tracker + Gmail application pipeline, browsed in a Tailscale-only PWA.

**Architecture:** Host cron agent `job-hunt` (Python + `claude` CLI, no tools) writes everything to `data/jobs.db` via a shared `JobStore`; `jobs_ui/` is a FastAPI + Alpine PWA over the same store with no LLM.

**Tech Stack:** Python 3.12 stdlib (`sqlite3`, `html.parser`, `zipfile`, `difflib`), `requests`, FastAPI, Alpine.js, pytest.

**Spec:** `docs/superpowers/specs/2026-10-15-job-hunt-design.md`

- [[2026-10-15-job-hunt-design]] · [[Design Docs]]

## Global Constraints
- Location: `location=Netherlands`, `f_WT` ∈ {2 (remote), 3 (hybrid)}, `f_TPR=r172800`.
- No hard-coded role titles or sectors — queries come from the CV (validated ≤ 40 chars, `[\w .+/#-]`).
- `untrusted_input = True`, `mcp_config = None`, no `allowed_tools` on `JobHuntAgent`.
- Every LLM output field re-validated in Python (score clamped 0–100, enums coerced, strings sanitised + capped).
- Telegram ping threshold: score ≥ 75; `parse_mode=None`; each job notified at most once.
- Gmail: 90-day backfill on first run, 7-day window after; dedup by message id.
- CV: newest `Cian_Hughes_CV_General*` Google Doc or `.docx`; token `~/.google_tokens_drive_ro.json`, scope `drive.readonly`.
- Score cap: 40 jobs scored per run; 2 s between LinkedIn requests; 429 aborts the fetch step.
- UI renders text with `x-text` only (never `x-html`); port 8774 bound to the Tailscale IP.

## Review Focus
1. LinkedIn returns HTML with no cards / changed markup → fetch yields 0 jobs, run still completes (test in Task 1).
2. LLM returns prose, fenced JSON, ids it was never given, or out-of-range scores → ignored/clamped, never crash (Tasks 4–5).
3. Same Gmail message seen twice / two emails for the same application → one application, two events, no duplicates (Task 2, Task 5).
4. "applied" email arriving after a "rejected" one → status is not downgraded (Task 2).
5. Drive unavailable (token missing) → falls back to last stored CV snapshot instead of failing the run (Task 4).

### Task 2: `agents/job_store.py`
**Files:** Create `agents/job_store.py`, `tests/test_job_store.py`.

**Produces:** `DEFAULT_JOBS_DB`, `validate_query(q) -> str | None`, `normalise_company(name) -> str`, `class JobStore(path=DEFAULT_JOBS_DB)` with:
- CV: `latest_cv() -> dict|None`, `add_cv_snapshot(file_id, name, modified_time, text) -> dict`, `text_hash(text) -> str` (static)
- Queries: `list_queries(enabled_only=False)`, `replace_cv_queries(list[str]) -> int`, `add_manual_query(q) -> dict` (ValueError on invalid/dupe), `delete_query(id) -> bool`
- Jobs: `has_job(id)`, `insert_job(job) -> bool`, `jobs_needing_triage(limit)`, `set_triage(id, keep)`, `jobs_to_score(limit)`, `set_description(id, text)`, `save_score(id, score, matched, gaps, rationale, cv_id)`, `reset_scores_since(days) -> int`, `list_jobs(status=None, min_score=None)`, `get_job(id)`, `set_job_status(id, status)`, `jobs_to_notify(min_score) -> list`, `mark_notified(ids)`, `mark_applied(job_id) -> dict` (application)
- Applications: `list_applications()` (each with `events`), `get_application(id)`, `create_application(company, role, status, source, job_id=None, notes="") -> dict`, `update_application(id, status=None, notes=None) -> dict|None`, `find_application(company, role) -> dict|None`, `record_email_event(company, role, status, message_id, thread_id, subject, occurred_at) -> dict` (find-or-create + event + rank-guarded status + job link)
- Gmail: `gmail_seen(msg_id) -> bool`, `mark_gmail_seen(msg_ids)`, `has_gmail_history() -> bool`

Status rank guard: `applied=0 < interview=1 < offer=2`, `rejected=2`, `withdrawn=2`; an email event only moves status to an equal-or-higher rank.
